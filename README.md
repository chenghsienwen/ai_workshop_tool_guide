## Site structure

```
index.html              top-level entry (安裝環境 / 手作步驟)
install/index.html       OS picker (installation guide entry)
windows.html              generated from ai_workshop_guide_windows.html (gitignored)
macos.html                generated from ai_workshop_guide_macos.html (gitignored)
workshop/index.html      hands-on session picker
workshop/session-N.html  per-session hands-on steps
```

## Local Run

The guides are self-contained HTML files with no build step. `windows.html` and `macos.html`
are generated by CI at deploy time (never committed) — edit the `ai_workshop_guide_*.html`
sources instead, then sync local copies to preview:

```bash
cp ai_workshop_guide_windows.html windows.html
cp ai_workshop_guide_macos.html macos.html
python3 -m http.server 8080
```

Then open:
- http://127.0.0.1:8080/ — top-level entry
- http://127.0.0.1:8080/install/index.html — OS picker
- http://127.0.0.1:8080/windows.html
- http://127.0.0.1:8080/macos.html
- http://127.0.0.1:8080/workshop/index.html — session picker

`windows.html` and `macos.html` are gitignored, so there's no risk of accidentally committing them.
Everything under `install/` and `workshop/` is committed directly (no CI generation step).
